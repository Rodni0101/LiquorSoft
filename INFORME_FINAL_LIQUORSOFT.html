Fase 6 — Revisión funcional completa

Se revisaron y corrigieron los flujos principales:

  • Registro (Register): Se corrigió error 500 "Field 'password' doesn't have a default value". La tabla usuarios heredada tiene la columna password como NOT NULL, pero el INSERT solo llenaba password_hash. Se agregó la columna password al INSERT y se vinculó password_hash también a ella. Resultado: HTTP 201 "Cuenta creada correctamente" en ~0.4s.
  • Productos públicos (/api/products.php): Se corrigió error 500 por columna p.destacado inexistente en el esquema heredado. Se reemplazó por 0 AS featured en las 3 consultas (listado, detalle individual, productos relacionados). Soporte de producto individual (?id=) y productos relacionados ya funcionan.
  • Productos admin: SQL adaptado al esquema real: codigo→sku, marca_id→marca (JOIN marcas), grado_alcohol→graduación, costo→precio_compra.
  • Proveedores: Columnas renombradas: empresa→name, nit→identification. INSERT/UPDATE corregidos.
  • Compras: Tablas lotes, compras, detalle_compra creadas (no destructivo). Consulta y UPDATE de productos corregidos.
  • Proxy Angular: localhost → 127.0.0.1 en proxy.conf.json para que el frontend alcance al backend PHP.
  • Usuarios admin: Endpoints POST (crear), PATCH (editar rol/datos), DELETE (eliminar) implementados en backend/api/admin/users.php. Frontend con modal de crear/editar, filtros, búsqueda, badges de rol, confirmación de eliminación y toggle de estado.
  • Base de datos: Rol Cliente creado (id 7) para que el registro público funcione.

Fase 7 — Calidad del código y arquitectura

  • Build de Angular: PASA sin errores TypeScript ni de compilación.
  • Eliminada sección de métricas inexistente en /admin/ventas que llamaba a endpoint /api/admin/orders.php?metrics=1 no implementado (mostraba guiones "—").
  • Componente usuarios corregido: agregado standalone: true y removido CommonModule innecesario (usa control flow @if/@for de Angular).
  • Iconografía unificada con Bootstrap Icons; eliminados emojis problemáticos (🛒, ✓, !, ←) y flechas unicode del sidebar admin.
  • Conservada la arquitectura actual: no se cambió de framework, no se reescribió toda la arquitectura.

Fase 8 — Base de datos, seguridad e integridad

  • Sin operaciones destructivas: No se ejecutó schema.sql (tiene DROP TABLE). Solo se crearon tablas faltantes (lotes, compras, detalle_compra) y se agregó el rol Cliente.
  • Credenciales: No se expusieron secretos. El archivo .env sigue ignorado por Git.
  • CSRF: Cookie liquorsoft_csrf y encabezado X-CSRF-Token validados en operaciones mutables.
  • Autorización: requireRole valida roles en endpoints protegidos. Administrador no puede modificar/eliminar su propia cuenta.
  • Consultas preparadas: Todo el backend usa consultas parametrizadas (MySQLi prepared statements), inyección SQL mitigada.
  • Edad mínima: Validación de 18 años en backend para compra de licores (Ley 124 de 1994 Colombia).

Fase 9 — Accesibilidad, responsividad y rendimiento

  • Accesibilidad: roles ARIA, aria-live, aria-label, focus-visible con anillo, botones con cursor not-allowed al deshabilitar, labels en formularios, orden del foco.
  • Responsividad: media queries en chat, checkout, carrito, dashboard, admin-shell para móviles (≤560px, ≤760px, ≤900px).
  • Rendimiento: build optimizado, lazy-loading de rutas, tokens CSS centralizados, sin dependencias innecesarias.

Problemas pendientes y limitaciones

  • Chat (/api/chat.php): Retorna 503 porque la clave OpenAI está configurada pero el servicio de respuesta generativa no responde. Sin clave, usa respuestas locales. No es un bloqueo del core de la aplicación.
  • Endpoint /api/notifications.php: Referenciado por UserNotificationsService pero no existe en el backend. No afecta las funcionalidades principales de compra/venta.
  • PayPal: OAuth contra Sandbox verificado (HTTP 200). Si falla en producción, verificar credenciales y extensión cURL de PHP.

Instrucciones para ejecutar y verificar

  1. Iniciar MySQL y asegurar la base liquorsoft con los 7 productos existentes.
  2. Iniciar backend: php -S 127.0.0.1:8000 -t backend
  3. Iniciar frontend: cd LiquorSoft-angular && ng serve (requiere Node.js 22.22.3+)
  4. Abrir http://localhost:4200 y navegar por las vistas.
  5. Credenciales admin: admin123@gmail.com / Admin12345@
  6. Verificar endpoints con curl o Postman contra http://127.0.0.1:8000/api/
